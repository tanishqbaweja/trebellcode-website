What's new in 2.0

2.0.0 is the first major release since 1.6.0, and it is mostly about the coding agents you run inside Trebell. Muse Code is new, OpenCode 2 is supported, and every harness now brings its own models, approvals, sign-in and updates. We also redesigned the interface, made every turn show what it did, and made the app lighter on your machine.

Muse Code, Meta's coding agent

Meta's coding agent now runs inside Trebell. Sign in with muse login, and its replies, reasoning, commands and file edits stream into the thread. Its approvals and questions come to Trebell's own card and dialog, and Usage shows its 5-hour and weekly windows.

Each harness brings its own models

The model picker shows each harness's own models, options and default, and a reopened thread resumes on the model it used. Thinking shows as a collapsed Thinking row, OpenCode 2 runs beside OpenCode 1.x, and Settings offers an update when a harness has a newer release.

A redesigned interface

Every page now shares the same top bar. Replies render as GitHub-style Markdown, with tables and code blocks you can copy.

Every turn shows what it did

Each turn keeps an activity card that says what every step did, such as a command's exit code and duration or an edit's diff. A turn that failed or was stopped before it replied says how and why.

Native streams replies and waits out network drops

On OpenAI, Native's replies stream in as they are written, and code-change turns are checked before the answer. Native can look at images in your workspace, and it waits for the network instead of failing the turn.

Lighter on your machine

Trebell starts fewer background processes, uses less CPU and GPU while you type and replies stream, and opens large threads with much less disk and database work.

Why we built our own agent

The same model can do very different work depending on the harness around it: the tools it gets, the context it sees, how it recovers when something fails and how it checks its work. Trebell Native is the harness we build and tune ourselves, aimed at getting real repository work done reliably.

When the network drops

Long agent runs hit dropped connections and rate limits. If the harness gives up on the turn, the work done so far is lost.

  • New in 2.0: when a model request cannot connect, Native waits for the network and tries again every 60 seconds until it gets through or you stop the turn.
  • New in 2.0: on a rate limit, Native waits as long as the provider suggests, and with OpenAI reasoning models a dropped connection no longer loses the turn's reasoning.

Your real toolchain

An agent's commands run in your actual environment: your files, terminal, Git, worktrees, credentials and processes, with each provider's own quirks on top.

  • New in 2.0: commands Native runs keep your project's toolchain variables, so Ruby, Rust, Java, Go and Python builds find their tools, locally and on remote hosts.
  • New in 2.0: toolchain values that look like a password, secret, token or key are kept out of the commands Native runs.

Checking the work

An agent saying it is done does not mean the code works. Native checks before it answers.

  • New in 2.0: Native recognizes more ways of asking for a code change and checks its work on those tasks before it answers.
  • New in 2.0: when its check cannot confirm the work, Native says why, and keeps or restores the version of your files the evidence best supports.

How Native finds the right code

More context is not always better. Trebell Native reads the files that define a name first, searches beyond source code, and keeps long output out of the model's way without throwing it away.

  • Definitions firstThe files that define a name are read before the files that only use it, and results come back grouped by file.
  • Beyond source filesCode search also finds matches in docs, templates, configuration and changelogs, and a search can be limited to a folder or a glob.
  • Long output, keptOn long tasks, runs of identical output lines are collapsed for the model, with the full output still retrievable.

Trebell Native is our own agent runtime and harness

It runs its own model and tool loop and calls model APIs directly, with its own code search, permission modes, recovery and checks, instead of passing everything through another coding harness.

Lower cost for the same work

Good repository search, long output kept out of the prompt, context that stays stable for the cache, and sensible stopping and retries all cut cost without needing a smarter model.

Trebell Code 2.0 ships Trebell Native and runs seven more coding agents in one workspace with files, a terminal, Git and pull requests, worktrees, previews, a browser panel, projects and environments. Trebell Native's benchmark results are graded by an independent verifier.
