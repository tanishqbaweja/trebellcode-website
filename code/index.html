00The story

The model is only half the system.
The harness changes the result.

Trebell Code is our attempt to build a better coding harness around increasingly capable models. Trebell Native owns the agent loop, context strategy, tool execution, recovery, verification and telemetry. We benchmark it against established harnesses using the same model and task.

PRODUCT

A complete coding harness, not a chat wrapper

Trebell Native runs its own agent loop with repository context, terminals, files, Git/worktrees, browser verification, durable threads, permissions, recovery and model/tool telemetry.

THE BET

A better harness can make the same model materially better to use

Model quality matters, but so do context discipline, tool behavior, retry strategy, state, caching and verification. Those are systems problems Trebell can actually improve.

WHAT WE BUILT

Context, tools and recovery are first-class infrastructure

The Context Engine keeps large repositories retrievable instead of eagerly stuffing them into every turn. Tool execution is deterministic, state is durable, and failures can recover without restarting the whole job.

HOW WE MEASURE IT

Same model. Same task. Compare the harness.

We run Trebell Native against Codex API and OAuth lanes with pinned models and independent verifiers, then compare correctness, input/output tokens, cache behavior, tool calls, retries, agent time and cost.

WHY MULTI-RUNTIME EXISTS

Compatibility is useful. Trebell Native is the thing we are improving.

Codex, Claude Code and OpenCode can run inside the same desktop product, which gives users choice and gives us honest baselines. But Trebell Native is our own harness and the core optimization target.

BUSINESS MODEL

Open-source for developers. Team infrastructure when they scale.

The desktop harness is the product developers can adopt directly. The planned paid layer adds shared policy, usage controls, managed execution, audit and administration for teams running agents at higher scale.

02The problem

AI coding is becoming infrastructure.
The harness is the bottleneck.

The same capable model can behave very differently depending on the environment wrapped around it. Trebell focuses on the part a model vendor does not solve for you: the engineering system that turns inference into dependable repository work.

⌘01 / 03

Context becomes a tax.

Dumping more of a repository into every turn burns tokens, damages cache locality, and often gives the model less signal rather than more.

  • IN TREBELL Repository intelligence is retrievable instead of eagerly stuffed into every prompt.
  • IN TREBELL Large outputs can be virtualized while keeping hot previews available to the model.
◇02 / 03

Agents operate in brittle worlds.

Files, terminals, Git, worktrees, credentials, processes, permissions, side effects, crashes, and provider differences all become part of the agent’s actual runtime.

  • IN TREBELL Deterministic tools sit behind shared policy instead of bespoke provider behavior.
  • IN TREBELL State, source control, process handling, and recovery belong to the harness.
✓03 / 03

Completion is not proof.

An agent saying “done” is not the same as the software being correct. Real engineering needs evidence, not confidence theater.

  • IN TREBELL Verification evidence is part of the execution loop rather than an optional afterthought.
  • IN TREBELL Repairs are measured end-to-end instead of celebrating isolated micro-metrics.

04Context

Give the model what matters.
Keep the rest retrievable.

  • Progressive discoveryExpose specialized tools and MCP capability only when the task needs them.
  • Large-output virtualizationKeep bulky command output retrievable instead of replaying it through every turn.
  • Stable identityKeep project/thread state independent of whichever model provider is active.

05Efficiency

Optimize useful coding work.
Not vanity metrics.

Trebell measures the harness where it can actually control the result: provider input, cache behavior, model turns, tool calls, failures, retries, and unnecessary inference. No pretending noisy upstream provider latency is a harness breakthrough.

  • Token & cache telemetrySee where context is paid for, reused, or wasted.
  • Tool/retry accountingMeasure how much orchestration the model needed to reach a verified result.
  • Regression disciplineAn optimization only counts when the end-to-end task gets better.

07Company

Build the better harness first.
Then make it team infrastructure.

The near-term product is Trebell Code itself: a serious desktop harness with its own native agent runtime. The longer-term company layer is the infrastructure teams need once agent usage becomes shared, expensive and operationally important.

Core product

Trebell Native is our own agent runtime and harness.

It owns the controller loop, repository context, tool orchestration, state, recovery, permissions, verification and usage telemetry instead of relaying everything through another coding harness.

Efficiency thesis

Inference should be spent on useful engineering work.

Repository retrieval, output virtualization, cache-stable context, stopping behavior and retry discipline are all places where a harness can reduce cost without asking the underlying model to become smarter.

Execution

The product already exists beyond the pitch.

The current product includes a native agent loop, external runtime adapters, durable SQLite state, Git/worktrees, terminals, browser verification, permission policy, recovery, packaging and a benchmark harness with external verifiers.

Next milestone

Prove the pattern across more unseen software work.

Terminal-Bench 4.0 is the current external program. SWE-Bench Pro V2 is the next software-engineering target. The goal is repeatable harness gains across independent tasks, not one pretty benchmark.

Position

Provider-independent, but not dependent on somebody else’s harness.

Trebell can use different model providers directly through its native route while also supporting external runtimes for compatibility. That keeps model choice separate from the engineering system we are actually building.

Team layer

The same harness becomes more valuable when usage is shared.

The planned commercial layer adds organization policy, shared usage and cost controls, managed execution environments, auditability and administration without changing the underlying developer workflow.

The point

Better models help. Better harnesses make every model go further.

Trebell Code is not trying to claim the model does not matter. It is trying to make the surrounding engineering system measurable and improvable. If the same model can reach the same verified result with fewer paid tokens, fewer retries and less wasted work, that is a real product improvement.
